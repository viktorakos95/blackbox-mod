# Patch sets, dependencies and presets

Generated by `python3 tools/combo.py table` from `tools/patchsets.py`. Do not edit by hand.

All the code is compiled once into one block (the cave). A set only adds the hooks that point into it, so choosing sets never makes the image smaller:
the cave is 157,260 of 188,808 bytes (83%, 31,548 free); the build fails if it overflows. The MCL program is a separate block (~402 KB, MCL 5.10+).

Notes:

- `tools`: comp registers the settings, tools only shows them. Without a machine the settings do nothing useful.
- `looper`: The SONG button cycles Looper -> SAMPLR -> TRIG -> DRONE-8 -> (MCL) -> stock song screen (solo.c solo_song_pressed). All those pages are tabs of the Looper page (looper_page.c), so SAMPLR, Trigger2MIDI and the DRONE-8 page cannot be left out while `looper` is in, nor offered without it.
- `hide_drone`: Without `hide_drone` the DRONE-8 page is in the round, and it needs the engine: `lira` (see PAGE_NEEDS).
- `lira`: The DRONE-8 page itself is part of `looper`; without `looper` the engine is only the pad mode.
- `lirarec`: Does not need `lira`: test_lira_rec passes on an image without it (checked). The list only offers the machines whose page is in the image.
- `lirasave`: Comes with every part (tools/combo.py from_parts). Does not need `lira`: the state is allocated by a `filter` hook, and test_lira_save / test_lira_roundtrip pass on an image with `lirasave` and no `lira` (checked). Shares two hook points in the card task (0x080743E8, 0x0807443E) with `mclsd`: with both in the image the cave's hook runs first and calls MCL's.
- `mclblob`: Needs `looper` (the MCL page is a tab of it) and `cpu` (cpu_boot starts the blob). Must be applied after `cave`.
- `mclsd`: TWO forms: with `lirasave` in the image it writes cave variables (the chain above), without it it hooks the card task itself. The form is chosen by whether `lirasave` is in the list (patches/mclsd.py reads sys.argv), so a per-set export needs both.

Dependency evidence: every `requires` comes from the module's own docstring and the source (`evidence` in `tools/patchsets.py`). No test builds a set WITHOUT what it requires, so the rule is the safe one, not a proven minimum: combinations that break it are never offered.

## Presets

| preset | sets | what |
|---|---|---|
| `core` | 14 | 3.1.n features only (no machines) |
| `looper-family` | 18 | Looper, SAMPLR, Trigger2MIDI + Tools settings (no DRONE-8) |
| `drone-family` | 19 | DRONE-8 with Looper, SAMPLR, Trigger2MIDI |
| `all` | 21 | Everything except MCL |
| `all+mcl` | 23 | Everything with MCL (experimental) |

The 3.1.n features (`solo`, `slice`, `duck`, `chord`, `cond`, `filter`, `cpu`, `od`, `comp`, `seqfix`, `savexml`, `fx2`, `munchi`) are one bundle in every combination: the tests only cover them together.

## Parts and add-ons (free combinations)

Pick any parts; the page leaves out whatever is not picked. All the pages are tabs of the Looper page, so any part brings the `looper` hooks (the host) and the others get a `hide_*` set (`bb_hide` in the cave: the SONG round, BACK, MIX and the pad recorder's Rec Input list skip a page that is hidden). Every part works alone or with any other.

| part | sets | left out with |
|---|---|---|
| Looper | `looper` | `hide_looper` |
| SAMPLR | `looper` | `hide_samplr` |
| Trigger2MIDI | `looper` | `hide_trig` |
| DRONE-8 | `looper`, `lira` | `hide_drone` |
| MCL | `looper`, `mclblob`, `mclsd` | not adding its sets (no blob, no page) |

| add-on | sets |
|---|---|
| Tools settings (`tools`) | `tools` |
| Record DRONE-8 / Looper / SAMPLR onto a pad (`rec`) | `lirarec` |
| MIDI clock monitor (`clkmon`) | `looper`, `clkmon` |
| Restart record (`crash`) | `crash` |

Rules the page enforces (`problems()` in `tools/combo.py`): a set needs what `requires` says; the DRONE-8 page needs `lira`; `looper` with every page hidden shows nothing. `python3 tools/combo.py resolve parts=samplr,trig addons=tools` prints the sets of a combination.

Not decided by the parts yet: the Tools settings page lists all its machine settings whenever `tools` is in (a DRONE-8 Out setting with no DRONE-8 does nothing).

## Tested (docs/combos.json)

`tests` counts the emulator tests that apply plus the wiring check (every hook of the chosen sets present, every other set's sites stock). A test applies when every image it names is made of the combination's sets and the pages it walks are in the image; it then runs on the combination's own image. Scope `full` = every applicable test; `fast` = the hook-sensitive tests and the page tests only (the other tests do not depend on which hooks are in: they pass on an image with none, and run in full on the presets and the single parts).
